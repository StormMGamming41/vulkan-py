# Vulkan Commands

## What are Vulkan Commands?

>[!NOTE]
>My explanation about this might have some flaws, incorrect information that I might have misunderstood, or something else.
>Do not forget to check your knowledge against verified sources, even if most of it is correct.

All the functions defined by Vulkan that we call to use various features of the Vulkan API are called *commands* in the context of Vulkan.

All Vulkan commands follow a similar naming convention. Each one begins with the `vk` prefix (*case-sensitive*) and takes arguments depending on its level. Instance-level and device-level commands have a fixed first argument, while global commands are an exception to this. You'll understand this better when you look at the classification below.

## Classification of Commands

At the highest level, Vulkan commands are classified into three types:

- Global Commands
- Instance-Level Commands
- Device-Level Commands

### Global Commands

In Vulkan, global-level commands are those commands that are loaded directly through the Vulkan loader library, like `vulkan-1.dll` on Windows or `libvulkan.so` on Linux.

At the time of writing this guide and developing `vulkan-py`, there are four core global commands that Vulkan exposes. They're listed below.

- `vkEnumerateInstanceVersion` - This command queries the loader about the highest Vulkan API version supported by the system. It is available with Vulkan 1.1 and above. For compatibility with Vulkan 1.0 loaders, this command may not be available. *For some reason, this command is not yet defined in `vulkan-py` like the rest of the global commands.*

- `vkEnumerateInstanceLayerProperties` - This command is used to query the available Vulkan layers, like `VK_LAYER_KHRONOS_validation`, on the current system.

- `vkEnumerateInstanceExtensionProperties` - This command is used to query the available instance extensions on the current system, or the extensions available for a specific layer.

- `vkCreateInstance` - This command takes three arguments, which, in the correct order, are:

  - A reference to a `VkInstanceCreateInfo` structure containing valid data.
  - An optional allocator, which is usually skipped or set to `None` in our case. Vulkan then uses its default allocation callbacks.
  - A reference to an empty `VkInstance` handle, to which it assigns the newly created instance.

Usually, `vkCreateInstance` is all we need from these commands, unless we explicitly want to query the Vulkan loader about the features and extensions provided by the Vulkan API.

### Instance-Level Commands

These commands are associated with a Vulkan instance, and their first argument is always a `VkInstance` handle. Unlike global commands, these commands are generally not loaded directly through the loader's exported functions. Instead, they are **dynamically loaded** at runtime, based on the instance they are being loaded for and the extensions and layers enabled for that particular instance.

The address of these commands, or in simple words, a pointer to one of them for a specific instance, can be obtained through the `vkGetInstanceProcAddr` command. It takes the following arguments:

- **Instance** - A `VkInstance` handle pointing to the instance being used.
- **pName** - The name of the command whose function pointer we want to retrieve.

Some examples of instance-level commands are:

- `vkDestroyInstance`
- `vkEnumeratePhysicalDevices`
- `vkGetInstanceProcAddr`
- `vkCreateDevice`
- etc.

But luckily, you don't have to go through the painful process of retrieving function pointers for the enormous number of commands. The `vulkan-py` library has an entire `Instance` wrapper class for this. Just pass the instance handle to the class, and you can access the instance-level commands as attributes of the wrapper class, as shown below:

```python
from vulkan_py import Instance, VkInstance

# your code ...

instance_handle = VkInstance(...)

instance = Instance(instance_handle)

# your code ...

instance.vk*(...)
```

>[!NOTE]
>Here, `*` represents any instance-level command available through the `instance` object, provided that it is supported for the instance.

### Device-Level Commands

These commands are associated with a logical device object in Vulkan, and their first argument is always a `VkDevice` handle. Similar to instance-level commands, these commands are generally **dynamically loaded** at runtime, based on the logical device they are being loaded for and the extensions and layers enabled for that device.

The address of these commands for a specific device can be obtained through the `vkGetDeviceProcAddr` command, which takes the following arguments:

- **Device** - A `VkDevice` handle pointing to the logical device.
- **pName** - The name of the device-level command whose function pointer we want to retrieve.

Some examples of device-level commands are:

- `vkGetDeviceProcAddr`
- `vkDestroyDevice`
- `vkAllocateMemory`
- `vkGetDeviceQueue`
- etc.

Similar to the `Instance` wrapper, the library also provides a `Device` wrapper class for the device-level commands available for the `VkDevice` handle passed to it. It can be used as shown below:

```python
from vulkan_py import Device, VkDevice

# your code ...

device_handle = VkDevice(...)

device = Device(device_handle)

device.vk*(...)
```

>[!NOTE]
>Here, `*` represents any device-level command available for the logical device object that the `VkDevice` handle is pointing to, provided that it is supported for that device.

>[!IMPORTANT]
>When using dynamically loaded commands through the `Instance` and `Device` wrapper classes, the first argument, which is `VkInstance` / `VkDevice`, does not need to be passed manually, as it is automatically supplied by the wrapper itself.
